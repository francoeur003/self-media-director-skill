# 数据合同

## 目录

- 历史视频 CSV
- 候选选题 CSV
- EDL JSON
- 输出文件

## 历史视频 CSV

一行代表一条已发布视频。文件顺序默认从最早到最新；如果相反，运行脚本时加 `--newest-first`。

必需字段：

| 标准字段 | 可识别中文字段 | 说明 |
|---|---|---|
| `published_at` | `发布时间`、`发布日期`、`日期` | ISO 日期优先，如 `2026-07-01 20:00` |
| `views` | `播放量`、`浏览量`、`观看次数` | 支持 `1.2万`、`35k` |

推荐字段：

| 标准字段 | 可识别中文字段 | 用途 |
|---|---|---|
| `title` | `标题`、`视频标题` | 追溯具体内容 |
| `topic` | `主题`、`选题`、`内容支柱` | 选题评分必需 |
| `format` | `形式`、`视频形式` | 区分口播、教程、Vlog 等 |
| `likes` | `点赞`、`点赞量` | 互动质量 |
| `comments` | `评论`、`评论量` | 互动质量 |
| `shares` | `分享`、`转发` | 传播质量 |
| `saves` | `收藏`、`收藏量` | 内容价值 |
| `followers` | `发布时粉丝数`、`粉丝数` | 账号规模校正 |
| `duration_sec` | `时长`、`视频时长` | 时长诊断 |
| `completion_rate` | `完播率` | 支持 `38%` 或 `0.38` |

示例：

```csv
published_at,title,topic,format,views,likes,comments,shares,saves,completion_rate
2026-07-01 20:00,新手剪口播最容易犯的3个错,口播剪辑,教程,18200,920,86,144,310,41%
2026-07-04 12:30,我把4分钟废片剪成了45秒,口播剪辑,案例,29600,1500,132,280,460,48%
```

不要把自然流量与付费投流视频混用。若无法拆分，新增 `paid` 字段并在分析前过滤。

## 候选选题 CSV

| 字段 | 必需 | 说明 |
|---|---|---|
| `topic` | 是 | 与历史数据中的主题标签尽量一致 |
| `angle` | 是 | 具体切入角度，而不是大类 |
| `hook` | 推荐 | 可直接说出的首句 |
| `payoff` | 推荐 | 观众最终看到的结果或证据 |
| `format` | 否 | 口播、教程、案例、Vlog 等 |
| `trend_score` | 否 | 0–100；只有有来源的近期趋势才高于 70 |
| `strategic_fit` | 否 | 0–100；与账号定位和商业目标的匹配度 |
| `effort` | 否 | 1–5，1 为最省制作成本 |
| `source` | 否 | 趋势、评论区需求或竞品证据来源 |

## EDL JSON

时间单位为秒。只保留 `segments` 中的片段并按数组顺序拼接。

```json
{
  "segments": [
    {"start": 12.4, "end": 18.8, "label": "最强结果开场"},
    {"start": 2.1, "end": 11.9, "label": "问题与方法"},
    {"start": 19.2, "end": 42.6, "label": "演示与证据"}
  ]
}
```

## 重点字幕约定

在 SRT 字幕正文开头加 `【重点】`，表示整条字幕需要重点样式：

```srt
12
00:00:18,200 --> 00:00:20,400
【重点】真正影响完播的，是前面这一个气口。
```

渲染时会移除 `【重点】`，并用更醒目的字号和颜色显示该句。只标真正需要观众记住的句子；普通字幕不要加标记。

## 输出文件

```text

├── final.mp4
├── qc_report.json

├── traffic_forecast.md
├── candidates.csv

└── next_video_brief.md
```
